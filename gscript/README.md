# แบบสอบถามเดลฟาย รอบที่ 2 และรอบที่ 3 — Google Apps Script Web App

โปรเจกต์นี้เป็นเว็บแอปที่รันบน Google Apps Script สำหรับแบบสอบถามเดลฟาย
**รอบที่ 2** (`Index.html`) และ **รอบที่ 3** (`Round3.html`) แยกหน้ากันคนละ
URL parameter โดยใช้ข้อคำถามชุดเดียวกันทั้ง 127 ข้อ (เวอร์ชันตามเอกสาร PDF
ล่าสุด) และบันทึกคำตอบแต่ละรอบลง Google Sheet คนละแท็บกันโดยอัตโนมัติ
พร้อมชีตอ้างอิงรายการคำถามทั้งหมดไว้ให้ผู้วิจัยดูคู่กัน ก่อนเริ่มตอบ ผู้ตอบต้อง
"เข้าสู่ระบบ" ด้วยรหัสผู้เชี่ยวชาญ (`res01`–`res21`, รวม 21 ท่าน) ทุกรอบ — ระบบ
จะตรวจสอบว่ารหัสนั้นเคยส่งคำตอบของรอบนั้นมาแล้วหรือยัง และบล็อกไม่ให้ตอบซ้ำ

หน้ารอบที่ 3 มีจุดต่างจากรอบที่ 2 คือ **ไม่เก็บส่วนที่ 1 (ข้อมูลทั่วไป) ซ้ำ**
(เก็บไปแล้วในรอบ 2) และ**แต่ละข้อคำถามจะดึงคำตอบเดิมของผู้ตอบคนนั้นในรอบที่ 2
มาตั้งเป็นค่าเริ่มต้นให้ พร้อมแสดงกราฟค่ามัธยฐาน/ช่วง Q1–Q3/IQR ของกลุ่มในรอบ 2**
ไว้ประกอบการยืนยันหรือทบทวนคำตอบ (จับคู่ข้อมูลด้วย username เดียวกัน) นอกจากนี้
ยังมีหน้า **`?page=printround3`** สำหรับผู้วิจัยพิมพ์แบบสอบถามรอบ 3 เป็นกระดาษ/PDF
รายบุคคล (พร้อมข้อมูลอ้างอิงชุดเดียวกัน) ให้ผู้เชี่ยวชาญที่ไม่สะดวกใช้เว็บแอป

## โครงสร้างไฟล์

- `Questions.gs` — **แหล่งข้อมูลคำถามหลักเพียงที่เดียว** (`SECTIONS`) ครอบคลุมทั้ง
  5 ด้าน (P/O/CM/Co/CT) ใช้ทั้งฝั่งเว็บฟอร์มและฝั่งชีตอ้างอิง แก้คำถามที่ไฟล์นี้
  ไฟล์เดียวพอ
- `Code.gs` — server-side script:
  - `doGet(e)` เสิร์ฟหน้าเว็บตาม `?page=` ที่ส่งมา (ไม่ใส่/`index` = รอบ 2,
    `round3` = รอบ 3, `stat` = สรุปผลสถิติรอบ 2, `statr3` = สรุปผลสถิติรอบ 3,
    `printround3` = หน้าพิมพ์รอบ 3) ฝัง `SECTIONS` เป็น JSON เข้าไปในหน้าฟอร์ม
    ตอน render และสร้างชีต `คำถามอ้างอิง` อัตโนมัติถ้ายังไม่มี (เฉพาะตอนเข้า
    หน้ารอบ 2)
  - `checkRespondentStatus(username)` / `checkRound3Status(username)` —
    ตรวจสอบรูปแบบรหัส (`res01`–`res21`) และเช็คว่าเคยมีคำตอบของรหัสนี้ใน
    รอบนั้นแล้วหรือยัง เรียกจากหน้า Login ก่อนแสดงแบบสอบถาม ฝั่งรอบ 3 จะ
    คืนคำตอบเดิมของผู้ใช้คนนั้นจากชีต `Responses` (รอบ 2) พร้อมมัธยฐาน/Q1/Q3/
    IQR/ผลผ่านเกณฑ์ของกลุ่มรอบ 2 มาด้วย เพื่อให้หน้าฟอร์มตั้งค่าเริ่มต้น แสดง
    อ้างอิง และตัดสินใจว่าข้อไหนต้องมีช่องความคิดเห็นเพิ่มเติม (ดูหัวข้อ
    "ช่องความคิดเห็นเพิ่มเติมสำหรับข้อที่ไม่ผ่านเกณฑ์" ด้านล่าง)
  - `submitSurvey()` / `submitRound3Survey()` — รับข้อมูลจากฟอร์มแล้วบันทึก
    เป็นแถวใหม่ในชีต `Responses` หรือ `Responses_R3` ตามลำดับ (ตรวจซ้ำอีกครั้ง
    ภายใต้ `LockService` ว่ารหัสนี้ยังไม่เคยส่งของรอบนั้น เพื่อกันกรณีเปิดสอง
    แท็บส่งพร้อมกัน) — ทั้งสองรอบเก็บข้อมูลคนละชีต ไม่ปะปนกัน
  - `getPrintRound3Data(key, username)` — ใช้โดยหน้า `?page=printround3`
    รวมข้อมูลคำตอบเดิม + สถิติกลุ่มของผู้เชี่ยวชาญคนหนึ่งเป็นรายการเดียว
    พร้อมจัดวางพิมพ์
  - `refreshQuestionReference()` ฟังก์ชันที่รันเองได้จาก Apps Script editor
    (เมนู Run) เพื่อล้างและเขียนชีต `คำถามอ้างอิง` ใหม่ทั้งหมดหลังแก้ไข
    `Questions.gs`
- `Index.html` — เทมเพลตหน้าฟอร์มรอบ 2 (โครงหน้า/สไตล์/สคริปต์ฝั่งไคลเอนต์)
  โดยดึงรายการคำถามจาก `Questions.gs` ผ่านตัวแปร `sectionsJson` ที่ `doGet()`
  ฝังให้ ไม่ได้ฮาร์ดโค้ดคำถามไว้ในไฟล์นี้แล้ว
- `Round3.html` — หน้าฟอร์มรอบ 3 โครงคล้าย `Index.html` แต่ไม่มีส่วนที่ 1 และ
  แต่ละข้อจะแสดงกราฟสไลเดอร์ "คำตอบเดิมของท่าน (รอบ 2)" + Median + ช่วง
  Q1–Q3 ของกลุ่ม (สีแยกกันชัดเจน) พร้อมตั้งค่าเริ่มต้นของตัวเลือกตามคำตอบเดิม
  ให้อัตโนมัติ (ยืนยัน/แก้ไขได้) เข้าถึงผ่าน `?page=round3`
- `PrintRound3.html` — หน้าพิมพ์แบบสอบถามรอบ 3 เป็น A4 แนวตั้ง/PDF สำหรับ
  ผู้เชี่ยวชาญที่ไม่สะดวกใช้เว็บแอป เข้าถึงผ่าน `?page=printround3` ต้องใส่
  รหัสผ่านผู้ดูแลระบบ + รหัสผู้เชี่ยวชาญที่ต้องการพิมพ์ ดูรายละเอียดที่หัวข้อ
  "หน้าพิมพ์แบบสอบถามรอบ 3" ด้านล่าง
- `Stat.html` / `StatR3.html` — หน้าสรุปผลสถิติ (มัธยฐาน/IQR) ของรอบ 2 และ
  รอบ 3 ตามลำดับ แยกจากหน้าฟอร์มโดยสิ้นเชิง เข้าถึงผ่าน `?page=stat` และ
  `?page=statr3` ต้องใส่รหัสผ่านผู้ดูแลระบบก่อนถึงจะเห็นข้อมูล ดูรายละเอียด
  ที่หัวข้อ "หน้าสรุปผลสถิติ" ด้านล่าง
- `appsscript.json` — manifest กำหนดค่าเว็บแอป (deploy แบบให้ทุกคนเข้าถึงได้
  โดยไม่ต้องล็อกอิน)

## วิธีติดตั้ง (ผ่านเว็บ script.google.com)

1. สร้าง Google Sheet ใหม่ (ไฟล์นี้จะเป็นที่เก็บคำตอบ) ตั้งชื่อตามต้องการ เช่น
   "ผลตอบแบบสอบถามเดลฟาย รอบที่ 2"
2. ในชีตนั้น ไปที่เมนู **ส่วนขยาย (Extensions) → Apps Script**
3. ในโปรเจกต์ Apps Script ที่เปิดขึ้นมา ลบไฟล์ `Code.gs` เริ่มต้นแล้วสร้างไฟล์
   ใหม่ตามชื่อในโฟลเดอร์นี้:
   - สร้างไฟล์สคริปต์ชื่อ `Code` แล้ววางเนื้อหาไฟล์ `Code.gs`
   - สร้างไฟล์สคริปต์อีกไฟล์ชื่อ `Questions` แล้ววางเนื้อหาไฟล์ `Questions.gs`
   - สร้างไฟล์ HTML ชื่อ `Index` แล้ววางเนื้อหาไฟล์ `Index.html`
   - สร้างไฟล์ HTML ชื่อ `Round3` แล้ววางเนื้อหาไฟล์ `Round3.html`
   - สร้างไฟล์ HTML ชื่อ `PrintRound3` แล้ววางเนื้อหาไฟล์ `PrintRound3.html`
   - สร้างไฟล์ HTML ชื่อ `Stat` แล้ววางเนื้อหาไฟล์ `Stat.html`
   - สร้างไฟล์ HTML ชื่อ `StatR3` แล้ววางเนื้อหาไฟล์ `StatR3.html`
   - เปิดไฟล์ `appsscript.json` (ต้องเปิดใช้งาน "Show appsscript.json" ผ่าน
     ไอคอนฟันเฟือง Project Settings → Show "appsscript.json" manifest file
     in editor) แล้วแทนที่ด้วยเนื้อหาไฟล์ `appsscript.json` ในโฟลเดอร์นี้
4. ใน `Code.gs` แก้ค่าตัวแปร `STAT_ACCESS_KEY` (บรรทัดบน ๆ ของไฟล์) จาก
   `'CHANGE_ME_ADMIN_KEY'` เป็นรหัสผ่านที่คุณต้องการใช้เข้าหน้าสรุปผลสถิติ
   — **อย่าลืมขั้นตอนนี้** ไม่เช่นนั้นใครก็ตามที่เดารหัสเริ่มต้นได้จะเข้าดูผล
   ก่อนคุณ
5. บันทึกโปรเจกต์ทั้งหมด (Ctrl/Cmd+S)
6. กด **Deploy → New deployment**
   - เลือกประเภท **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone** (หรือ Anyone with Google account ถ้าต้องการ
     จำกัดผู้ตอบ)
   - กด Deploy แล้วอนุญาตสิทธิ์การเข้าถึง (authorize) ตามที่ระบบขอ
7. คัดลอกลิงก์ **Web app URL** ที่ได้ แล้วส่งให้ผู้เชี่ยวชาญที่จะตอบแบบสอบถาม
   รอบที่ 2 (ลิงก์นี้เปิดหน้าแบบสอบถามรอบ 2 โดยตรง) ส่วนหน้าอื่น ๆ อยู่ที่ลิงก์
   เดียวกันบวก query string ต่อท้าย:
   - แบบสอบถามรอบ 3: `?page=round3`
   - พิมพ์แบบสอบถามรอบ 3 เป็น PDF/กระดาษ (สำหรับผู้วิจัย ต้องใส่รหัสผ่าน):
     `?page=printround3`
   - สรุปผลสถิติรอบ 2 (สำหรับผู้วิจัย ต้องใส่รหัสผ่าน): `?page=stat`
   - สรุปผลสถิติรอบ 3 (สำหรับผู้วิจัย ต้องใส่รหัสผ่าน): `?page=statr3`

พอเปิดเว็บแอปครั้งแรก ระบบจะสร้างชีต **`คำถามอ้างอิง`** ให้อัตโนมัติ ในนั้นมี
รหัสข้อ, หมวด/ด้าน, ระดับ (หลัก/ย่อย) และข้อความคำถามครบทั้ง 127 ข้อ ไว้ให้ผู้วิจัย
เปิดดูคู่กับคอลัมน์ในชีต `Responses` ได้ทันที (ไม่ต้องเปิดอ่านโค้ด)

เมื่อมีผู้ตอบแบบสอบถามและกด "ส่งแบบสอบถาม" ระบบจะสร้างชีตชื่อ `Responses`
ในสเปรดชีตเดียวกัน พร้อมสร้างหัวตารางอัตโนมัติในการบันทึกครั้งแรก
(คอลัมน์ `timestamp`, `username` + ข้อมูลส่วนที่ 1 + ทุกรหัสข้อคำถาม
P.../O.../CM.../Co.../CT... + `part3_suggestion`) และเพิ่มแถวใหม่ทุกครั้งที่มีการส่งฟอร์ม

### หน้า Login / กันตอบซ้ำ

ก่อนเห็นแบบสอบถาม ผู้ตอบต้องกรอกรหัสผู้เชี่ยวชาญในรูปแบบ `res01`–`res21`
(พิมพ์ตัวพิมพ์ใหญ่/เล็กก็ได้ ระบบจะแปลงเป็นตัวพิมพ์เล็กให้อัตโนมัติ) กด
"เข้าสู่ระบบ" แล้วระบบจะ:

- ถ้ารหัสนั้น**ยังไม่เคยส่งคำตอบ** → แสดงแบบสอบถามให้ตอบตามปกติ (มีป้ายชื่อ
  รหัสผู้ตอบกำกับไว้ด้านบนตลอด)
- ถ้ารหัสนั้น**เคยส่งคำตอบไปแล้ว** → แสดงข้อความแจ้งว่าเคยตอบไปแล้วเมื่อไร
  และไม่แสดงแบบสอบถามให้ตอบซ้ำ

ไม่มีรหัสผ่านแยกต่างหาก (ใช้ username เพียงอย่างเดียวตามที่ตกลงไว้) จึงเหมาะ
กับกลุ่มปิดที่รู้รหัสกันอยู่แล้วเท่านั้น หากต้องการความปลอดภัยเพิ่มในอนาคต
สามารถเพิ่ม PIN ต่อรหัสได้ที่ `RESPONDENT_PATTERN`/`normalizeUsername_`
ใน `Code.gs`

### แบบสอบถามรอบที่ 3 (`?page=round3`)

หน้ารอบ 3 มี login แบบเดียวกัน (username `res01`–`res21`, บล็อกการตอบซ้ำ) แต่
เก็บคำตอบลงชีตแยกต่างหากชื่อ **`Responses_R3`** (ไม่ปะปนกับชีต `Responses`
ของรอบ 2) **ไม่มีส่วนที่ 1 (ข้อมูลทั่วไปของผู้เชี่ยวชาญ)** เพราะเก็บไปแล้วในรอบ 2
และมีจุดต่างสำคัญคือ **แต่ละข้อคำถามจะแสดงข้อมูลอ้างอิงจากรอบ 2** ให้ทันทีหลัง
login สำเร็จ ในรูปแบบกล่องข้อความ + กราฟสไลเดอร์แนวนอน (สเกล 1–5):

- **คำตอบเดิมของท่าน (รอบ 2)** — ดึงมาจากแถวของ username เดียวกันในชีต
  `Responses` แสดงเป็นชิปสีแดง + วงกลมโปร่งบนกราฟ และตั้งเป็นตัวเลือกที่ถูก
  เลือกไว้ล่วงหน้าในตัวเลือกคะแนน 1–5 ทันที (ผู้ตอบกดข้ามไปข้อถัดไปได้เลยถ้า
  เห็นด้วยกับคำตอบเดิม หรือจะเลือกใหม่ทับก็ได้)
- **มัธยฐานกลุ่ม (Median)** — ชิปสีกรมท่า + จุดทึบบนกราฟ
- **ช่วง Q1–Q3 (IQR)** — ชิปสีทอง/เหลือง + แถบสีบนกราฟ พร้อมป้าย
  "✓ ผ่านฉันทามติ"/"ยังไม่ถึงฉันทามติ" — คำนวณสดจากชีต `Responses` ทุกครั้งที่
  มีคน login (ไม่ต้องรอผู้วิจัยกดคำนวณที่หน้า stat ก่อน)
- ถ้า username นั้นไม่มีคำตอบในรอบ 2 (เช่น เพิ่งเข้าร่วมภายหลัง) ชิป
  "คำตอบเดิม" จะแสดง "ไม่มีข้อมูล" และไม่ตั้งค่าเริ่มต้นให้ แต่ยังเห็นค่ากลุ่ม
  ตามปกติ และยังตอบรอบ 3 ได้โดยไม่ถูกบล็อก
- ถ้าข้อใดยังไม่มีข้อมูลกลุ่มเพียงพอในรอบ 2 (เช่น ยังไม่มีใครตอบข้อนั้นเลย)
  จะแสดง "ยังไม่มีข้อมูลกลุ่มเพียงพอสำหรับข้อนี้" แทนกราฟ (และนับเป็น "ไม่ผ่าน
  เกณฑ์" ด้วย จึงมีช่องความคิดเห็นแสดงเช่นกัน — ดูหัวข้อถัดไป)

ส่วนที่ 1 (ข้อมูลทั่วไปของผู้เชี่ยวชาญ) เก็บไปแล้วในรอบ 2 จึงไม่ถามซ้ำ ส่วนที่ 3
(ข้อเสนอแนะเพิ่มเติม) ยังคงให้กรอกได้ท้ายแบบสอบถามเหมือนเดิม

### ช่องความคิดเห็นเพิ่มเติมสำหรับข้อที่ไม่ผ่านเกณฑ์

ทุกข้อที่ **ไม่ผ่านเกณฑ์ฉันทามติของรอบ 2** (median < 3.50 หรือ IQR > 1.50 —
ป้ายแสดง "ยังไม่ถึงฉันทามติ") จะมี**กล่องข้อความให้ผู้เชี่ยวชาญกรอกความคิดเห็น
เพิ่มเติมของตัวเองสำหรับข้อนั้นโดยเฉพาะ** ต่อท้ายตัวเลือกคะแนน 1–5 ทันที
(กรอกหรือเว้นว่างก็ได้ ไม่บังคับ) ส่วนข้อที่ผ่านเกณฑ์แล้วจะไม่มีกล่องนี้ ไม่มีการ
เปลี่ยนแปลงใด ๆ

ความคิดเห็นที่กรอกจะถูกบันทึกลงชีต `Responses_R3` เป็นคอลัมน์แยกต่อท้ายคอลัมน์
ของข้อนั้น ๆ โดยใช้ชื่อคอลัมน์รูปแบบ `<รหัสข้อ>_comment` (เช่น คอลัมน์คะแนนของ
ข้อ P3.5 อยู่ที่คอลัมน์ `P3.5` ความคิดเห็นจะอยู่ถัดไปที่คอลัมน์ `P3.5_comment`)
โดยอัตโนมัติ ไม่ต้องตั้งค่าอะไรเพิ่มฝั่งชีต — ระบบจะสร้างคอลัมน์เหล่านี้ให้เอง
ตอนมีคนส่งแบบสอบถามครั้งแรกที่มีข้อไม่ผ่านเกณฑ์

หน้าพิมพ์ (`?page=printround3`) มีกล่องเดียวกันนี้เป็นเส้นบรรทัดว่าง ๆ ให้เขียน
ด้วยปากกา สำหรับข้อที่ไม่ผ่านเกณฑ์เช่นกัน (ไม่มีในกระดาษของข้อที่ผ่านเกณฑ์แล้ว)

### หน้าพิมพ์แบบสอบถามรอบ 3 (`?page=printround3`)

สำหรับผู้เชี่ยวชาญบางท่านที่ไม่สะดวกตอบผ่านเว็บแอป — หน้านี้ให้ผู้วิจัยกรอก
**รหัสผ่านผู้ดูแลระบบ** (`STAT_ACCESS_KEY` เดียวกับหน้าสรุปผลสถิติ) และ
**รหัสผู้เชี่ยวชาญ (username)** ที่ต้องการพิมพ์ให้ แล้วระบบจะสร้างแบบสอบถาม
รอบ 3 ฉบับกระดาษที่มีข้อมูลอ้างอิงชุดเดียวกับหน้าเว็บ (คำตอบเดิมของคนนั้นในรอบ
2, กราฟมัธยฐาน/Q1–Q3/IQR ของกลุ่ม, ช่องความคิดเห็นสำหรับข้อที่ไม่ผ่านเกณฑ์)
พร้อมวงกลมตัวเลข 1–5 ว่าง ๆ ให้ผู้เชี่ยวชาญวงด้วยปากกาแทนการกดในเว็บ (วงกลม
ที่ตรงกับคำตอบเดิมของคนนั้นจะมีขอบหนา + ป้าย "เดิม" กำกับไว้ ไม่ต้องอ่านชิป
ข้อความเพื่อหาว่าเคยตอบข้อไหนไว้)

กดปุ่ม **"พิมพ์ / บันทึกเป็น PDF"** จะเรียก dialog พิมพ์ของเบราว์เซอร์ (จัด
หน้าเป็น A4 แนวตั้งให้อัตโนมัติผ่าน CSS) เลือกเครื่องพิมพ์จริงหรือเลือก
"Save as PDF"/"บันทึกเป็น PDF" ก็ได้ — ถ้าสีบนกราฟไม่ขึ้นตอนพิมพ์ ให้เปิด
ตัวเลือก "Background graphics"/"พื้นหลังกราฟิก" ใน dialog พิมพ์ของเบราว์เซอร์
ก่อน (ค่าเริ่มต้นของบางเบราว์เซอร์จะปิดไว้)

คำตอบที่กรอกบนกระดาษต้องให้ผู้วิจัยนำไป**คีย์เข้าระบบเองภายหลัง** (เช่น เปิด
`?page=round3` แล้วตอบแทน หรือกรอกลงชีต `Responses_R3` ตรง ๆ ให้ตรงกับ
คอลัมน์ `username`, รหัสข้อคำถาม, และคอลัมน์ `<รหัสข้อ>_comment` สำหรับข้อที่
มีความคิดเห็นเขียนไว้) หน้านี้มีไว้สร้างกระดาษให้ตอบเท่านั้น ไม่มีการบันทึก
อัตโนมัติ

### หน้าสรุปผลสถิติ (`?page=stat` และ `?page=statr3`)

เข้าได้จากลิงก์เว็บแอปเดียวกัน โดยต่อ `?page=stat` (รอบ 2) หรือ `?page=statr3`
(รอบ 3) ท้าย URL เช่น `https://script.google.com/macros/s/XXXXX/exec?page=stat`
สองหน้านี้แยกจากหน้าฟอร์มโดยสิ้นเชิง (คนละไฟล์ คนละ URL parameter) และมีไว้
สำหรับผู้วิจัยเท่านั้น — ต้องกรอก**รหัสผ่านผู้ดูแลระบบ** (ค่าที่ตั้งไว้ใน
`STAT_ACCESS_KEY` ของ `Code.gs`, ใช้รหัสเดียวกันทั้งสองหน้า) ก่อนถึงจะเห็น
ข้อมูลใด ๆ โครงหน้าเปล่า ๆ เปิดดูได้จากลิงก์ตรง ๆ แต่ตัวเลขสถิติทั้งหมดจะถูก
ส่งมาจากเซิร์ฟเวอร์ก็ต่อเมื่อรหัสผ่านถูกต้อง

สิ่งที่แต่ละหน้าคำนวณให้ต่อข้อคำถามทุกข้อ (`?page=stat` อ่านจากชีต `Responses`,
`?page=statr3` อ่านจากชีต `Responses_R3` — คนละชุดข้อมูลกัน คำนวณสดทุกครั้ง
ไม่ต้อง refresh สเปรดชีตเอง):

- **n** — จำนวนคำตอบที่เป็นตัวเลขของข้อนั้น
- **มัธยฐาน (Median), Q1, Q3, IQR (Q3−Q1)** — คำนวณด้วยวิธี linear
  interpolation แบบเดียวกับฟังก์ชัน `QUARTILE`/`PERCENTILE` (แบบ `.INC`) ใน
  Google Sheets เพื่อให้ตัวเลขตรงกันหากผู้วิจัยลองคำนวณเทียบเองในชีต
- **ค่าเฉลี่ย (Mean)** — ไว้ดูประกอบเพิ่มเติม
- **ผลการพิจารณา** — ผ่านเกณฑ์เมื่อ median ≥ 3.50 และ IQR ≤ 1.50 (ตามเกณฑ์
  เดียวกับที่แจ้งไว้ในหน้าคำชี้แจงของแบบสอบถาม)

ปุ่ม **"บันทึกผลลงชีต Google Sheet"** จะเขียนผลทั้งหมด ณ ขณะนั้นลงชีตชื่อ
`สรุปผลสถิติ` (จากหน้า `?page=stat`) หรือ `สรุปผลสถิติ รอบ 3` (จากหน้า
`?page=statr3`) — ทับของเดิมทุกครั้งที่กด — ให้เป็นสำเนาถาวรไว้อ้างอิงใน
วิทยานิพนธ์โดยไม่ต้องเปิดหน้าเว็บย้อนมาดูอีก ส่วนปุ่ม **"คำนวณใหม่"** แค่
รีเฟรชตัวเลขบนหน้าจอ ไม่แตะชีตใด ๆ

## วิธีติดตั้งด้วย clasp (ทางเลือกสำหรับสาย dev)

หากต้องการพัฒนา/deploy จากเครื่องด้วย [clasp](https://github.com/google/clasp):

```bash
npm install -g @google/clasp
clasp login
cd gscript
clasp create --type webapp --title "Delphi Round 2 Survey" --rootDir .
clasp push
clasp deploy
```

`clasp create --type webapp` จะสร้างสเปรดชีตแบบ standalone ให้ใหม่
หากต้องการผูกกับ Google Sheet ที่มีอยู่แล้ว ให้ใช้ `clasp clone <scriptId>`
ของสคริปต์ที่ผูกกับสเปรดชีตนั้นแทน

## หมายเหตุ

- ทุกครั้งที่แก้จำนวน/รหัสข้อคำถามใน `Questions.gs` (ตัวแปร `SECTIONS`) ให้:
  1. ลบชีต `Responses` เดิมทิ้งก่อนเปิดรับคำตอบชุดใหม่ ไม่เช่นนั้นหัวตารางเดิม
     จะไม่ตรงกับข้อคำถามชุดใหม่ (สคริปต์จะเติมค่าตามหัวตารางที่มีอยู่แล้วในชีต
     เสมอ ไม่สร้างคอลัมน์ใหม่ให้เอง)
  2. รันฟังก์ชัน `refreshQuestionReference` จาก Apps Script editor (เลือกฟังก์ชัน
     นี้ที่แถบด้านบนแล้วกด Run) เพื่ออัปเดตชีต `คำถามอ้างอิง` ให้ตรงกับคำถามชุดใหม่
- ใช้ `LockService` เพื่อป้องกันข้อมูลชนกันเมื่อมีผู้ตอบพร้อมกันหลายคน
